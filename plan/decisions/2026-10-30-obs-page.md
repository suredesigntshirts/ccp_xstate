# obs-page: how the page reads the journal, and where its refresh rows go

**Date:** 2026-10-30, 19:20Z
**Decided by:** the obs-page thread (two-way doors; the person was away)

- **Published page, not a repo-served page.** The page is a claude.ai artifact declaring `files` on this project, so
  it reads `/mnt/project-files/harness/journal` as the viewer, live, with nothing copied into the artifact. The source
  stays in `plugins/harness/pages/observe/`; `observe.html` is built from it and is the file published.
- **One data layer for page and tests.** `build.mjs` inlines `data.js`, `time.js` and `attention.js` into the page,
  each in its own scope, rather than reimplementing the views in the page. A test runs the bundled script and compares
  it with the modules, and fails when `observe.html` is stale.
- **page.refresh rows go to the page's store.** `files` is read-only, so the page cannot append to the journal. Each
  read writes a journal-shaped `page.refresh` row (session `page-observe`, the page as its only writer) to its `db`
  collection `refresh`, which sessions read with ArtifactData. Pulling them into the journal folder is left until a
  view needs them there.
- **No timers.** It reads once after it loads and on Refresh; nothing runs while nobody looks.
- **Scopes.** A day is the rows written that UTC day; a thread is every row of the sessions whose person, card or post
  rows name it; a session is its rows. Time by kind is the time view over the scoped rows, so a day cuts sessions at
  midnight.
- **The page's release** is stamped at build (`--release`), the release the page ships in (0.1.9 for the first; 0.1.8 went out while it was built). The
  journal's release shown beside it is the newest release among the rows read.
- **The test journal** (`test/fixtures/rows.jsonl`) is three real sessions at their real times, made by
  `test/fixtures/make.mjs` through the real capture code from recorded inputs: obs-time-and-rework's headless session
  with a subagent, the wf-quick-fix thread's card, tap and message, and the probe's classifier refusal. No live thread
  has capture rows yet: threads still start on the release their container cached.
