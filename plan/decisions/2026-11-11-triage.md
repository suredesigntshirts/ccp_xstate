# Triage of the open plan items, 11 Nov

The person asked on 10 Nov whether the queue still held work worth doing, and on 11 Nov said "Do the triage
'Apply it all', but don't start any work." Each open item was judged against what v2 is now: four workflows as data,
one engine pinned on xstate 5.33.3, and the goal of retiring v1 on measured numbers. An item stays only if it moves
that goal or fixes a defect on main; queued is not a reason.

## Kept, unchanged

- `second-workflow`: running different work through different workflows is the point of v2, and no real item has run
  through feature or research yet. It still waits on the person's pick.
- `derive-view-gaps`: the overhead, time and rework views are wrong today, and `parity-compare` reads them.
- `parity-compare`, `decide-v1-retirement`: the measured end of the plan.
- `retire-unmarked-reading`: the last place the engine guesses a workflow's rules.
- `inspector-exporter-shape`: restores a lost check on the person's main view of a workflow.

## Changed

- `parity-compare` no longer waits on `second-workflow`. v1 and v2 compare on the quick-fix items both have run; the
  second workflow adds its own column once it has run. What still blocks it is v1's numbers, which only a thread in
  the ccp_machine project can export (`waiting-for-person.md`).
- `actors-module-seam` no longer waits on `run-message-and-budget`. The edge was file order on the run modules, not a
  need.
- `refine-leftovers` is trimmed to the defects still on main, and `fix-gate-reads-renames` is merged into it: a
  one-flag gate fix does not pay for its own builder and verifier. Left out: the step-2 check in a frozen suite, the
  whitespace rule for rule-text tests, moving the artifact generators into `scripts/`, and the three points the
  refine rounds considered and did not take. Each is wording about rules, not a defect a run met.

## Dropped or parked

- `retire-brief-file-fallback`, dropped: 314 moved history files to delete a fallback of about ten lines that nothing
  new writes.
- `run-message-and-budget`, parked: designing the run message and budget twice buys elegance while no run has shown
  them conflict. It comes back when one does.
- `wf-schema`, `wf-catalogue`, `probe-xstate-runtime`, dropped: done in practice. Workflows are XState JSON files the
  engine loads through `packages/engine/src/spec.js`, `workflows/` holds four of them, and xstate is pinned.
- `wf-fragments` and `v1-history-import` stay parked until the comparison asks for them.

## Not taken

Merging every small item into one cleanup item. Items whose files do not overlap can run in parallel, and a grab bag
of unrelated checks is harder for a verifier to prove.
