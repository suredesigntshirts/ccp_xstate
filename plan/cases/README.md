# Parity cases

Real situations v1 met. v2 is on par when each live case has a passing test. Each case gives where it came
from, the situation, and what v2 must do. A case states behaviour, not mechanism, so the engine may meet it
in any way that fits.

Add a case whenever a real item finds a new situation. Items cite cases by id in `cases`.

```
### C-<slug>
**From:** the v1 issue, PR or ledger row.
**Given / When / Then:** the situation and the required outcome.
```
