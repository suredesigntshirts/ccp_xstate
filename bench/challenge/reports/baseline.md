## What the baseline shows (hand-written)

The first draft of `workflows/intake/challenge.md` failed every planted hole on every run (fails-planted 12/12): the half-met README line, the after-merge line, the adopted wrong fix, the ambiguous line and the missing CSV line. It is too strict on sound issues: clean-shout FAILs 3/3, on a docs line the request asked for, and clean-average FAILs once. That is the variant's target (`reports/variant-good-faith.md`), because a challenger that fails sound issues sends every item to the card after two revisions.

The first run of the clean cases and of planted-ambiguous (in `runs/first-cases/`) found real holes in those cases as first written: a test line that did not require an assertion, a request for the published site that pages.yml cannot render from markdown, a non-empty line that a `|| 0` build met, and a missing non-empty line in planted-ambiguous. The cases were corrected (each case's `source` says how) and those three cases were run again at the same workflow version (git 04e09ac); the 21 runs here are the corrected set.

The judge for evidence-grounded, catches-traps and avoids-must-not sees the case repository's file contents: the challenge's evidence makes claims about what code does, which a file list cannot confirm.
